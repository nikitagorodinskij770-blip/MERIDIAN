# MERIDIAN — бэкенд

Настоящий сервер: SQLite с двойной записью, матчинг-движок, подписанные запросы.
Только стандартная библиотека Python — ни одной внешней зависимости, потому что
на машине нет ни Node, ни pip-пакетов, и потому что для этой задачи их и не нужно.

## Запуск

```bash
python -m server.app 8787
```

Отдаёт и API (`/v1/*`), и фронтенд со статики — на `http://127.0.0.1:8787/`.
База создаётся при первом запуске в `server/meridian.db`.

Самопроверка денежного контура:

```bash
python -m server.selftest
```

## Два решения, определяющих всё остальное

**Деньги — целые числа.** Ни одной суммы во float. Каждый актив хранится в своих
минимальных единицах (сатоши, вэй, копейки), масштаб задан в `assets.scale`.
`0.1 + 0.2 != 0.3` в двоичной плавающей точке, и биржа, которая этого не учла,
теряет доли центов на каждой сделке, а потом не может свести баланс.

**Двойная запись.** Баланс — не поле, которое обновляют, а следствие журнала
проводок. Каждая операция создаёт минимум две записи в `ledger_entries`, их сумма
обязана равняться нулю; несбалансированная операция отклоняется до записи в базу.
`balances` — лишь материализованный кэш, поддерживаемый триггером, и расхождение
кэша с журналом ловится представлением `v_ledger_imbalance`.

Практический результат: `GET /v1/health` в любой момент отвечает, сходится ли
журнал, а `/v1/admin/integrity` показывает, где именно разошлось.

## Устройство

| Файл | Назначение |
|---|---|
| `schema.sql` | DDL: ограничения, индексы, триггеры, представления |
| `db.py` | подключение, справочники, `post_tx()` — единственный способ двинуть баланс |
| `security.py` | scrypt-пароли, сессии, подпись запросов HMAC-SHA256 |
| `engine.py` | матчинг «цена-время», расчёты по сделкам, ввод и вывод |
| `app.py` | HTTP: маршруты, аутентификация, CSP, отдача статики |
| `selftest.py` | 26 проверок инвариантов денежного контура |

## Подпись запросов

Канонизируемая строка одинакова на сервере (`security.canonical_string`) и на
фронтенде (`js/api/sign.js`):

```
METHOD \n PATH \n TIMESTAMP \n NONCE \n SHA256(body)
```

Подписывается HMAC-SHA256 на секрете ключа. Секрет по сети не ходит: клиент шлёт
`X-Api-Key`, `X-Timestamp`, `X-Nonce`, `X-Signature`. В браузере секрет
импортируется в `CryptoKey` с `extractable: false` — даже свой же JS не достанет
его обратно.

Три независимые преграды повторному проигрыванию: окно ±30 с по времени,
одноразовый `nonce` в таблице `request_nonces`, и включение тела запроса в подпись.

Проверено сквозным сценарием: браузер подписывает через WebCrypto, Python
принимает; подделка секрета даёт `BAD_SIGNATURE`, повтор nonce — `NONCE_REUSED`.

### Хранение секретов ключей

Проверка HMAC требует самого секрета, поэтому «хранить только хэш» здесь не
работает. Компромисс: секрет лежит зашифрованным на секрете экземпляра
(`.instance_secret`, отдельный файл вне базы). Утечка одного лишь дампа базы
ключи не раскрывает. В проде это место занимает KMS или HSM.

## Что здесь настоящее, а что нет

Настоящее: схема и SQL, двойная запись, матчинг с приоритетом «цена-время»,
scrypt, HMAC-подпись, защита от повторов, ограничение частоты, журнал аудита,
проверка сходимости.

Ненастоящее: деривация депозит-адресов (`_derive_address` выдаёт случайную
строку нужного формата вместо HD-вывода из xpub), зачисление депозитов (вызывается
руками, а не воркером, читающим блокчейн), 2FA (поле есть, проверки нет),
рассылки. Всё это отмечено в коде и описано в `../PLAN.md`.

## Коды ошибок

Конверт ответа — `{ "data": ..., "error": null }` либо
`{ "data": null, "error": { "code", "message" } }`.

| code | HTTP | Когда |
|---|---|---|
| `UNAUTHORIZED` | 401 | нет или просрочена сессия |
| `BAD_SIGNATURE` | 401 | подпись не совпала |
| `NONCE_REUSED` | 401 | запрос повторён |
| `TIMESTAMP_OUT_OF_WINDOW` | 401 | часы разошлись больше чем на 30 с |
| `FORBIDDEN` | 403 | ключу не выдано право |
| `ACCOUNT_BLOCKED` | 403 | счёт заблокирован |
| `KYC_REQUIRED` | 403 | вывод без верификации |
| `INSUFFICIENT_BALANCE` | 422 | недостаточно средств |
| `DUPLICATE_TX` | 422 | депозит с таким хэшем уже зачислен |
| `RATE_LIMITED` | 429 | превышена частота |
